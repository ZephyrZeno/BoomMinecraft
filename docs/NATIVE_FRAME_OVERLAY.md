# 原始 native 的栈帧数据扩展

v113 完成独立的 native 回调支持，v114 正在验证默认诊断链接接入。`scripts/native-frame-overlay.py` 实现原始声明索引、数据生成、MASM 构建及独立 COFF 校验；登记一项 native 栈帧不等于实现它。十个现有提供者入口已通过独立适配，执行验证范围如下；游戏尚未启动。

## 为什么需要单独的数据扩展

v109 的普通 Java 汇编已经引用稳定的 `boom_trace_method<原始方法ID>` 符号。ABI3 运行时要求方法行位于同一个连续表内，不能为新 native 随意传入表外行指针。新增服务需要回调 Java 初始化器或构造器时，必须为其方法入口提供真实的 native 帧。

扩展程序保留原来的全部方法行和源符号，按原始方法 ID 合并 native 行，生成替代的帧数据对象。后续链接只能选择一个帧数据对象；普通 Java 的 ASM／COFF 无需重新生成。现有 ABI3 的 48 字节池、32 字节方法行及正常类型描述符保持一致。

程序批量登记锁定输入中的全部原始 native 声明，便于后续服务共用。它逐项核对原始类字节、加载器、native 访问标志、无 Java Code 的条件、方法计划、原始注解及可用类型身份。未绑定声明类保留不可用标志和空类型指针，不伪造类型。已有行发生冲突、原始 ID 重复或表超出运行时容量时拒绝生成。

## 当前已经验证的范围

两侧已生成并独立校验实际 COFF。服务器原表 498,909 行保留，合并后 501,044 行，其中原始 native 声明 2,138 项，新增数据行 2,135 项；客户端保留原表 563,773 行，合并后 570,401 行，其中 native 声明 6,631 项，新增数据行 6,628 项。原有三个 native 行按完整字段比对后复用。四项 Python 测试检查行身份保持、冲突／容量拒绝、不可用类型以及伪造声明的拒绝。

数据层证据仅覆盖来源、生成数据与实际对象文件。两侧进一步通过了独立诊断重链接与执行测试：三个直接调用的原始 native 入口、原始冷反射初始化回调、Object 构造器枚举、61 个类标志样例、13 项错误检查及八工作者 32,768 次查询。旧 Java ASM／COFF 未修改，本次重链接也没有重新汇编 Java。模块／加载器仍为明确夹具，完整 VM 和游戏尚未启动。`all_native_frames`、活动根、安全点及自动回收仍为 false；新增数据行不记作新增 native 实现。

## 下一步接入要求

独立提供者需要绑定同一个已验证帧扩展，将回调服务的原始入口改为真实汇编 enter／leave，并保证每条错误路径解除帧。选择器、全局定义索引和独立闭包校验器必须一致地替换原帧数据对象，拒绝两个表同时链接或包的帧身份不一致。完成后应重新执行原始构造器枚举及调用者查询，再接入构造器调用服务。

`native-frame-adapters.py` 实现独立入口适配：在来源核对后，只替换原提供者的入口桥接，保留元数据与汇编服务体的原始文本。它为实际 COFF 重新校验导入和定义，不改写旧包。`relink-framed-diagnostic.py` 与 `Test-FramedNativeProviders.ps1` 已完成上述两侧验证；原始闭包和适配器在链接前重新校验，所有记录的输入在链接后再次核对。

验证器和选择器现在可以在单个进程的调用链中复用刚完成校验的提供者对象，交接时仍核对包、校验记录、工具及共同输入散列。独立执行前校验从完整 load_packs 开始，不从任意 JSON 的 verified 标志恢复该进程内对象。旧验证器源码已另存，历史执行范围保持可追溯。

v114 的提供者依赖可显式声明已验证帧扩展；全局符号索引、闭包选择器和独立校验器统一选用替代对象，并检查它替换的是原批次的同一个帧数据对象。两个反射构造器 native 采用原始声明的真实帧。`Build-NativeFrameOverlay.ps1` 接入开发启动诊断的自动准备流程；该命令不增加玩家界面操作，也不把生成帧数据记作游戏启动。

大诊断表的汇编文本生成改为片段收集后一次合并。服务器 93,490 行、78,283,116 字节的规范化输出与修改前逐字一致，本机一次生成用时 1.257 秒。这是开发工具耗时测量，不是游戏性能基准。已链接映像仍接受完整的独立来源和 COFF 校验。

输入、类加载器、变换链、原始注解、类型布局、ABI 或内核实现变化均使扩展失效。未来模组变换必须在最终类型与方法集合冻结之后重建相关帧数据；现阶段不宣称支持动态重定义。
