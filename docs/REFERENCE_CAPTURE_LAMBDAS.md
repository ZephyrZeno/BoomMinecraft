# Normal reference-capturing Lambda expansion

The first reference-capture site added here is Log4j's
`ServiceLoaderUtil.loadServices`, class 52050/CP53. Its standard metafactory
site captures one `Set` and creates a `Predicate.test(Object): boolean`.
The implementation handle is the original same-host static
`lambda$loadServices$0(Set, Object): boolean`, method 510939. It is not a
replacement implementation of `Set.add` or `Object.getClass`.

The existing source writer, generated Class verifier and assembly generator
already support reference captures. The additional work extends their actual
runtime metadata. The old sparse overlay still rejects fields; its frozen
source and the completed 23-Class prefix remain unchanged. A separate append
path consumes that explicit prefix and accepted source contracts, preserving
old Class files, identities, method bodies and machine prefixes.

For this site the appended type is 109968, with methods 530906 through 530908
and field 193844, `private final synthetic c0: Set`. The generated normal
object has an 8-byte payload and one leading reference field. Its constructor
calls the original
Object constructor and stores its argument; the factory allocates a fresh
normal object, and the SAM reads that instance's field before calling the
original implementation. It does not capture a fixed host object or use a
private host-side reference table. Null capture is governed by the original
site/helper semantics.

The field and type namespaces advance together to 193845 and 109969. The new
field has a genuine Field64 row, declaring-Class range, UTF-16 name, FMAP
address function and runtime field-pointer entry. The normal runtime row
records the payload size and reference prefix. All 190 field pages remain
accounted for:
some belong to replaced metadata units, while 93 middle pages remain in one
unchanged parent COFF object. Every
old field record and name offset is retained. The Class/lookup metadata,
three Frames and actual dispatch tables are extended from the real current
image, preserving its later ordinary ResolvedMethodName addition.

The original selected `Predicate.test` interface table 13904 receives
`{receiver: 109968, target: 530908, error: 0}`. Component invocation uses a real
compiled original `invokeinterface` thunk and this table; directly calling
the abstract original SAM would not test interface dispatch.

The projection advances both type and field bounds in the NIO, RAF and Inflater
registrars, plus the relevant Class, Unsafe, reflection, constant-pool and
Access metadata. The actual Main attempt also exposed a stale UFMP name-length
guard: the field name arena grows from 1026493 to 1026495 UTF-16 units, while
the initial registrar projection retained the old length. Type-only capacity
auditing does not detect this. All four dimensions (types, fields, name units
and field pages) require integration. Original CP entries and bytes remain
unchanged. Source
catalogues with a deliberately bounded original-Class domain do not thereby
gain arbitrary hidden-Class reflection support.

The complete snapshot retains 15 spans. The generated failure bank grows
from 23 to 24 cells; selected native cells grow from 28951 to 28952. The ordinary
Class/name/Access banks grow by 1/2/1 cells, and the derived extra-root count
advances from 115 to 120. The ordinary source root count 29274 and native RMN

count
values; its remaining code, symbols, relocations and unwind data compare
equal. Root physical acceptance is separately finalized from actual objects.

The original generated bytecode verifier accepts the aggregate of 24 Classes, and
the actual/canonical adapter and metadata COFF comparisons have passed.
Independent physical checks cover all 193844 old Field64 records, the new
field, runtime row, Frames and receiver-table additions. A development JDK
oracle compares the exact original metafactory and the byte-identical
generated hidden Class, checking fresh factories, two-Set isolation and null
evaluation order. This reference is not an AOT runtime test.

The complete image links from 266 actual objects. An independent link produces
the same complete PE bytes; the actual graph has 83 roles and retains all 15
root spans. This establishes machine composition, not successful game startup.

The initial original Main attempt exits 70 without a timeout and is rejected
by the unchanged strict decoder. Its final Context is kind 20, PC 2, method
70790 (`AbstractQueuedSynchronizer.release(I)Z`); that propagation point does
not identify the first failing callee. One monitor acquisition remains, cleanup
flags are zero and teardown reports busy status 170. The original Main Class
initializer, Main body and help output have not completed. The failed reports
are retained; this run does not establish a verified startup prefix or captured
factory/SAM execution.

After the three registrars derive the correct name length, the corrected
266-object image passes an independent whole-PE relink and actual original
Main observation. The process exits 86 at a later source diagnostic after
15.875 seconds, without a timeout. Cleanup flags are 7, held monitors and the
registry lock are zero, and all resource owners close successfully. The 117
registered source tools and all observed inputs remain unchanged. The new
stop is `boom_batch_call_52041_90_186`, a standard metafactory site with
factory descriptor `(Set)Consumer`. Main Class initialization, its body and
help output still do not complete; this is a verified diagnostic observation,
not a complete Minecraft launch.

Four separate native component runs pass, with 74 reported original,
generated and interface entry calls plus two pending-Context guard calls.
The basic run verifies fresh factories, two-Set isolation and the real
interface results. Its null cases reach built-in kind 4 at the original helper's
PC 2/5/2; they do not establish materialized NPE or JDK-message equivalence.

The collection run first stops and joins the original background workers.
It retains the complete 15 root banks and adds only one closure as an extra
root. Two quiescent collections keep that closure, its Set and its exclusive
HashMap alive; original helper calls still work. After removing the closure
root, a third collection frees five objects and real heap-membership queries
show that all three queried objects were released. No reclaimed pointer is
dereferenced. This tests explicit quiescent collection.

The thread run uses four actual OS threads with normal Java Thread/FLS
ownership, four independent Sets and sixteen fresh closures. All join and
detach operations pass. A separate original Thread constructor creates a real
NPE; the factory and interface guard preserve its complete 32-byte Context,
including the same pending Throwable and a zero VM-plan value. Each of the
four runs passes all twelve cleanup checks and unchanged-input checks.

The four runs allocate 22 captured closures in total. They do not establish
shared-HashSet thread safety, automatic/concurrent GC, or game performance.
Complete Minecraft startup remains unfinished.
